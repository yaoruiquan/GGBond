# 文档维护规范

功能交付包含对应文档更新；没有相关变化时在交付说明中注明原因，不机械新增文档。

## 放置与同步

- `api/`：接口、鉴权、字段、错误、幂等、限制与调用示例。API 或权限变化时同步。
- `guides/`：使用及配置步骤；功能开关、配置默认值、支付流程变化时同步，中英文支付文档保持一致。
- `development/`：开发扩展契约、工作流程及本规范；协议或开发工具变化时同步。
- `operations/`：监控、部署、升级、回滚与退役。部署命令、环境项、数据恢复和运维边界变化时同步；部署专属说明仍优先维护现有 `deploy/` 文档，不复制全文。
- `plans/`：迁移路线、设计阶段和交接。记录日期、状态（待实施／进行中／已完成／已废弃）、范围和验收证据；未验证项明确标出。保留历史快照并说明后续记录，不把计划当成已实现。
- `project/`：背景、项目对比和决策上下文；项目定位变化时同步。
- `legal/`、`screenshots/`：合规正文和图片；合规路径受 Docker、前端 raw import、后端配置依赖，不得随意移动。

优先更新现有文档，索引只说明用途并链接，不重复正文。新增正式文档须更新 [文档中心](../README.md) 及 `.gitignore` 的逐文件白名单；临时调查、日志、数据库备份、凭据和私有配置不得开放跟踪。

移动或改名时同步仓库内相对链接、图片、README 各语言、文本路径和跟踪规则。外部网站路径不随本地移动而改写；如需更换外部来源，先确认实际发布位置，不假设本地变更已发布。

## 交付检查清单

- [ ] 功能、API、配置和部署变化已对应更新，或说明无需更新的原因。
- [ ] 新文档有索引入口；计划有日期、状态及真实验证证据，待办未冒充验收。
- [ ] 旧路径已搜索，文档与图片的本地目标存在；历史缺失项如实说明，不编造补齐。
- [ ] 使用 `git ls-files docs`、`git status --short --untracked-files=all` 和 `git check-ignore --no-index -v <路径>` 核查现有内容及新增文件；仅开放审核过的精确路径。
- [ ] `git diff --check` 通过，未误改业务逻辑、合规依赖路径或删除已有资源。
