## 3. 模型广场在哪，怎么开启

页面路径是 **`/model-plaza`**，不是 `/models` 或 `/model-market`。

当前通过前端代理访问 `/api/v1/model-plaza`，实测返回：

```json
{"code":404,"message":"Model plaza is not enabled"}
```

这是开关未开启的预期响应，不是缺少功能。没有检查当前数据库是否已有可展示的渠道数据。

### 配置步骤

1. 登录 `http://localhost:4000/login`。
2. 进入 `/admin/settings`，开启「模型广场」，按需设置必须登录和 Markdown 说明。
3. 进入 `/admin/groups`，配置有效分组和倍率。
4. 进入 `/admin/channels`，创建或编辑启用的渠道，关联启用且平台兼容的分组。
5. 配置明确的模型映射或模型定价，使渠道可以枚举支持的模型。映射和定价都为空时，可能没有模型展示。
6. 访问 `http://localhost:4000/model-plaza`。

**注意：**

- 上游 API 凭据应在 `/admin/accounts` 中配置，不是往渠道里随便填一个 API Key。
- 匿名访问不显示专属分组；必须登录设置、后台模式等限制也会影响访问。
- 开关名称为 `model_plaza_enabled`、`model_plaza_require_auth`、`model_plaza_description`。
- 开关关闭时后端返回 404；要求登录但未认证时返回 401。
- 真实网关调用还需要有效账号、平台兼容的路由和可用额度。能展示价格不等于已验证上游调用成功。

## 4. 国内模型如何使用

后端 `internal/domain/platforms.go` 和前端 `src/constants/platformCatalog.builtin.json` 已包含国内平台支持。

在账号管理中选择实际需要的平台，配置有效凭据，再关联正确的分组、模型和路由。使用供应商当前支持的模型 ID 做连通性和计费验证，不要照抄历史示例模型名。

本次没有使用真实供应商凭据发起收费请求，也没有完成国内平台逐项验收。

## 5. 如何重启新项目

先确认端口没有其他项目占用；不要批量强制杀死未知进程。

后端终端：

```bash
cd /Users/yao/LLM/GGBond/backend
set -a
source data/dev.env
set +a
DATA_DIR="$PWD/data" SERVER_HOST=127.0.0.1 SERVER_PORT=8080 go run ./cmd/server
```

前端终端：

```bash
cd /Users/yao/LLM/GGBond/frontend
VITE_DEV_PORT=4000 pnpm run dev --host 127.0.0.1 --strictPort
```

前端默认端口不是 4000，必须显式指定。停止时使用各自终端 Ctrl+C。
